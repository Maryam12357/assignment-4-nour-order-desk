# Assignment 4 — Nour's Order Desk

## Project Overview

Nour's Order Desk is a responsive order management application built using Next.js App Router and TypeScript.

The application allows users to create, view, update, and delete customer orders through a REST API.

The goal is to demonstrate full CRUD functionality, backend validation, frontend-to-backend communication, and proper HTTP response handling.

## Technologies Used

- Next.js (App Router)
- React
- TypeScript
- REST API using Next.js Route Handlers
- CSS Modules
- In-memory data storage
- Thunder Client for API testing

## Main Features

- Create new customer orders
- Display all existing orders
- View individual order details
- Edit customer and order information
- Update order status
- Delete orders with confirmation
- Automatically calculate order totals
- Validate incoming API requests
- Display loading, success, empty, and error states
- Responsive layout for desktop and mobile

```bash
cd assignment-4-nour-order-desk
```


### 4. Start the development server


Open http://localhost:3000 in your browser.

## REST API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/orders` | Retrieve all orders |
| POST | `/api/orders` | Create a new order |
| GET | `/api/orders/:id` | Retrieve an order by ID |
| PATCH | `/api/orders/:id` | Update an existing order |
| DELETE | `/api/orders/:id` | Delete an order |

Successful DELETE requests return HTTP 204 No Content.

The server validates incoming data and calculates order totals.

## Validation and Business Rules

- Customer name, phone number, and product name are required.
- Quantity must be a positive integer.
- Unit price must be a valid nonnegative number.
- Order IDs are generated by the server.
- Clients cannot change server-owned order IDs.
- Order totals are calculated by the backend.
- Invalid requests return HTTP 400.
- Unknown order IDs return HTTP 404.
- Failed validation does not modify stored orders.

## Storage Limitations

This project uses in-memory storage rather than a database.

Orders are not permanently saved and may be lost or reset when the server process restarts.

The application is intended for educational purposes and demonstrates REST API CRUD functionality without persistent storage.
